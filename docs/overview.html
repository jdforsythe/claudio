Engineering plan · macOS · Swift

Claudio reads Claude Code aloud, across every session you have open.

A native menu bar app that tails Claude Code's transcripts, speaks what matters with no gaps between sentences, stops the instant you type, and keeps track of several sessions at once so you can switch and catch up.

Status fully specified, not yet implemented Spec 14 documents, 49k words, in docs/ Platform macOS 15+, Swift 6, no Xcode required Default voice edge-tts, Swift port

01Why build it

Hearing Claude Code work is useful. A prototype (claude-speak) proved it: with voices far better than the built-in Mac ones, you can keep Claude in its normal terminal mode and listen as it goes. The prototype also showed exactly where the naive design breaks.

What the prototype got wrong

  • Each sentence is a full synthesis round trip plus a new player process. Audible gaps everywhere.
  • Nothing stops it. Submit a new prompt and it keeps reading the old answer.
  • Tracks one transcript at a time, picked by a heuristic. A second session is silently dropped.
  • Config is CLI flags that need a restart, plus a half-working web page.
  • Installs scripts into ~/.claude/tools and runs as a terminal background job with no UI.
  • Speaks every block equally, including "Let me read that file."

What Claudio does instead

  • Synthesizes two sentences ahead into one gapless audio queue. Gaps under 50 ms.
  • Cancels in about 35 ms when you submit a prompt, with a short fade so there is no click.
  • Discovers every live session automatically. One holds the voice; the others announce when they finish or need you.
  • Every setting applies on the next sentence. No restarts, no flags.
  • A real menu bar app with a popover, a floating HUD and a settings window. Zero footprint in ~/.claude unless you opt in.
  • Three levels per session: just answers, answers plus narration, or events only.

Performance budgets the design is held to

02How it works

Two executables share one Swift package. The app owns all state and is the only process that touches audio. A tiny command-line tool, claudio, lives inside the app bundle and does two jobs: it is the hook receiver that Claude Code executes, and it is the user's CLI. Both talk to the app over a local Unix socket.

The flow of one sentence

  1. Discover. FSEvents watches the transcript root. A new or changed .jsonl file maps to a session.
  2. Tail. One tailer per transcript reads from its saved offset to the end of file. It attaches at end of file on first sight, so history is never replayed.
  3. Parse and assemble. Each JSON line becomes a typed record. The turn assembler groups records into turns and emits speech items with a category: final answer, narration, tool call, tool result, thinking, or event.
  4. Arbitrate. The arbiter knows which session is active. It passes that session's items through the level filter and lets events from any session cut in briefly.
  5. Render. Markdown becomes speakable text: code blocks become "code block", tables become "Header: value" rows, paths become filenames, links become "link".
  6. Segment and schedule. Text is split into sentences. The scheduler keeps two segments synthesized ahead of the one playing.
  7. Play. PCM buffers are scheduled back to back on one audio player node. Cancel is a 15 ms volume ramp, then stop and reset.

03Behaviour contracts

These are the rules a reviewer should hold the implementation to. They came out of a decision-by-decision interview and are recorded individually in the decision log.

Categories and levels

Every speakable thing has one category. Each session has one level. Levels are cumulative.

LevelSpeaksDefault for
QuietEvents only: finished, needs permission, needs inputUser choice
AnswersEvents + final answersSessions that are not active
NarrateAnswers + narration ("I'll read the parser first") + tool call summaries ("Running: git status")The active session

Thinking and tool errors sit behind two global advanced toggles, both off. Subagents are not their own category: they appear as "Agent started" and "Agent finished" tool-call items on the parent session, and their internal narration is never spoken.

Who gets the voice

Exactly one session is active. Only its items are voiced. Events from any other session are announced between sentences and never cancel what is playing. Switching is manual: popover, HUD, hotkey, or CLI. Automatic focus-following is deferred because macOS gives no reliable way to know which Claude session's terminal is frontmost, especially inside Orca.

Playback modes of the arbiter. Announcements from background sessions can be injected in any mode except paused.

Catch-up

When you switch to a session with unread turns, Claudio says the session name and how many turns it is catching up on, then plays the final answer of each unread turn, oldest first, up to the last five. Narration and tool calls are never part of catch-up. It ends with "Live." if the session is mid-turn or "You're caught up." if it is idle. A skip-to-live control abandons the rest at any point.

04Reading the transcript

Claude Code writes one JSON object per line to ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl. Subagent transcripts live beside it in a subagents/ folder. The format is internal and can change in any release, so the parser is tolerant: every field is optional except type, unknown types are counted rather than rejected, and every classification rule has a fallback.

What a turn looks like on disk

RecordMeaning for Claudio

assistant, one line per content block, sharing message.idText, thinking or tool_use blocks. Each line carries the message's stop_reason.
user with a tool_result blockTool output. Spoken only when it is an error and the toggle is on.
system with subtype turn_durationThe turn ended.

permission-mode, last-prompt, queue-operation, attachment, file-history-snapshotRead for display or ignored.

Final answer or narration?

The one classification that matters most: is this text block Claude's answer to you, or Claude talking before a tool call? Three signals, in priority order.

Verified on Claude Code 2.1.290. A live session was tailed with a 20 ms poller while generating multi-block messages. All per-block records of one message arrive in a single write after the message completes, each already carrying the final stop_reason. Across roughly 2,000 records there were 45 end_turn values and zero nulls. The primary path is the production path; the other two are guards. One consequence: the transcript exposes text at message granularity, so narration before a long tool call becomes readable only when that tool call finishes generating. The MessageDisplay hook is the documented way to get it earlier if that ever matters.

Sessions, liveness, and names

  • A session appears on its first transcript write and leaves the list 24 hours after its last one. A lunch break never empties the list.
  • claude agents --json is polled every 10 seconds to attach the process id and mark sessions whose process has exited as "ended". Ended sessions stay listed so you can still catch up.
  • Names come from Claude's AI-generated title, falling back to the folder name. Each session gets a stable colour.
  • Orca sessions are ordinary Claude sessions whose working directory is a worktree. Extra Orca accounts that pin CLAUDE_CONFIG_DIR are covered by a list of additional roots in Settings.
  • Session state, including unread turns and their final answer text, is cached in Application Support so catch-up survives an app restart.

05Hooks and the claudio CLI

The transcript alone is a complete source. Hooks are an opt-in upgrade that gives three things the transcript cannot: a cancel signal within tens of milliseconds, an authoritative final answer (the Stop hook carries it), and status events such as "needs permission". Enabling hooks writes seven entries into ~/.claude/settings.json, each pointing at the claudio hook binary inside the app bundle.

The cancel path with hooks installed. Typical total is about 35 ms; the budget is 100 ms.

Installer rules

  • Read, parse, back up (last 10 copies kept), append our entries, write atomically, re-read to verify.
  • Never touch entries that are not ours. Orca writes its own managed hooks into the same file, and the user already has hooks there; both must survive install and uninstall byte for byte.
  • If the file does not parse, refuse and show the error. Never write to a broken file.
  • If the app has moved, the entries point at the wrong path. The app detects this on launch and offers a one-click repair.
  • All entries are async: true, so Claude Code never waits on Claudio. If the app is not running, the receiver exits 0 silently.

The CLI

Because the socket exists for hooks anyway, a user CLI is nearly free. It also makes the app scriptable from inside a Claude session: a /speak skill wraps it.

claudio status            # playback state, active session, backend, hooks
claudio sessions          # table of live sessions with level and unread count
claudio switch yard       # by id prefix, title, or path; no argument = this session
claudio level narrate     # set this session's level (uses CLAUDE_CODE_SESSION_ID)
claudio pause | resume | skip | live | mute | unmute
claudio say "build finished"
claudio hooks install | uninstall | status
claudio doctor            # 12 health checks: socket, roots, claude binary, hooks, Edge, voices, audio device
claudio render notes.md   # see exactly what the renderer would speak
claudio tail              # watch speech items as they are classified

06Speech pipeline

This is where the prototype's gaps and missing cancel are fixed. Backends return raw PCM buffers, not audio files. One AVAudioPlayerNode plays every buffer back to back, so a sentence boundary is just a marker and costs nothing. The scheduler keeps two sentences synthesized ahead of the one playing, which hides the network round trip behind short sentences.

Cancel without a click

Stopping audio mid-sample produces an audible click. Claudio ramps the player node's volume to zero over 15 ms in 1 ms steps, then stops and resets the node, restores the volume, and leaves it playing silence so the next buffer starts with no further latency. A test renders a sine wave through an offline engine, cancels at a random phase, and asserts no sample-to-sample jump above a threshold. It runs in CI with no audio device.

Captions that follow the word

edge-tts streams word boundary metadata alongside the audio. The HUD's caption highlights the word being spoken, mapped from audio offset to playback position. Apple's synthesizer reports word ranges through its delegate. OpenAI reports nothing, so words are spread proportionally across the sentence's duration.

07Voices

Backends implement one protocol: take a sentence, a voice and a rate, return a stream of PCM buffers and optional word boundaries, and stop promptly when cancelled. Three ship in v1.

default · network

Edge

A clean-room Swift port of the edge-tts protocol: Microsoft's free neural voices over a WebSocket. Supports rate and word boundaries. The protocol is unofficial and has broken before, so the constants live in one file and failure degrades gracefully.

fallback · offline · always present

Apple

AVSpeechSynthesizer writing PCM buffers. Standard voices are mediocre; Premium voices are decent after a one-time download in System Settings, and the app shows a hint until one is installed. Siri voices are not available to third-party apps.

optional · API key · paid

OpenAI

gpt-4o-mini-tts streaming raw PCM over HTTP. About 1.5 cents per minute of audio. Key stored in the Keychain. No word boundaries.

later · local

Kokoro and friends

Local neural models via a sidecar process fit the protocol but are deferred. The bundling story for a Python runtime and model download is more work than the whole v1 UI.

Per-sentence fallback. The primary backend is retried on the very next sentence.

09Settings and footprint

Nothing requires a restart. App settings live in UserDefaults and are observed by the core actors; a change applies on the next sentence. Per-session level is ephemeral by session id, with a per-project default stored in a small JSON file so a project you always monitor opens at Narrate. 10Testing and build

Testing

  • Fixtures. Twenty scrubbed real transcripts, each with the expected sequence of events. Text is replaced by same-length filler with markdown structure preserved; structural fields stay verbatim. Two fixtures probe whether the installed Claude Code populates stop_reason, so a format change fails a named test instead of silently misclassifying.
  • Core is pure Swift with an injectable clock and a recording playback sink, so every latency and ordering claim is asserted without audio hardware. Target coverage: 90 % lines.
  • Backends are tested against a local mock WebSocket server that speaks the Edge protocol byte for byte, including the time-based anti-bot token. One network-gated live smoke test runs only when explicitly enabled.
  • Integration tests replay fixtures through the whole pipeline and map one to one onto the twelve user stories in the PRD.
  • Manual QA checklist per milestone: two terminals plus Orca, headphone unplug, sleep and wake, Orca hooks present, Premium voice absent and present, network offline.

Build without Xcode

The developer machine has Swift 6.3 through the Command Line Tools and no Xcode. SwiftPM builds both executables; a short script assembles Claudio.app with its Info.plist, icon, sounds and resource bundle, and signs it ad hoc. Developer ID signing and notarization are documented as the release path. A pre-commit hook runs swift-format and SwiftLint. GitHub Actions on a macOS runner lints, tests with coverage, bundles the app, and on a version tag publishes a release with the zip, its checksum and the dSYM.

make lint test app      # format check, lint, unit + integration tests, bundle Claudio.app
make install            # copy to /Applications, relaunch
make logs               # stream the unified log for subsystem com.jdforsythe.claudio
claudio doctor          # health checks after install

12Decisions

Every choice and what it beat. The full log with dates is docs/13-decisions.md. A decision is changed only by adding a superseding entry.

D-01macOS only, personal-first, publishable later

Beat cross-platform via Electron or Tauri. Every quality problem lives where native audio and window APIs help; a web stack removes those tools.

D-02Swift and SwiftUI with SwiftPM, no Xcode

Beat Tauri, Electron, Python tray libraries and Go. Best HUD story, trivial login item, first-class AVAudioEngine, nothing to bundle. Tauri was runner-up but routes audio through Rust or WebAudio and has focus regressions for non-activating panels.

D-03Transcript tail plus optional hooks

Beat hooks-only and tail-only. The transcript is asynchronous and unstable, so it cannot carry control signals alone; hooks fire per message, so they cannot carry streamed text alone. Writing hook entries to settings.json was accepted; the objection was to scripts dumped in ~/.claude/tools.

D-04Three levels, not six checkboxes

The real modes are "tell me when it's done" and "let me monitor it". Three levels fit a segmented control.

D-05One active session plus event interrupts

Beat auto-follow and interleaving. One voice cannot serve two narrations; interleaving drowns the one you care about; focus has no official API.

D-06Catch-up is a digest of final answers, last five turns

Beat resume-live-only, full backlog, and asking every time. Final answers carry the information; narration is only useful live.

D-07No LLM condensation

User decision. Adds a network dependency, cost and a second voice of truth. Skip controls cover impatience.

D-08Cancel semantics and the 15 ms fade

A prompt in the active session is an unambiguous "I've read it". Events never cancel. The fade avoids clicks.

D-09Ctrl+Option hotkeys, rebindable

Beat plain Cmd+J/K/L, which a global hotkey would steal from the terminal and browser.

D-10Native edge-tts port as default, Apple as fallback, no Python

Beat bundled Python, Kokoro sidecar, OpenAI default, Apple Premium default. The user's preference is "voices much better than Mac" for free. Fallback is mandatory because the protocol is unofficial.

D-11PCM buffers, not audio files

Files reintroduce per-clip startup, gaps and no instant stop. One player node gives sub-5 ms gaps and immediate stop.

D-12Lookahead of two sentences

One cannot hide a 300–800 ms round trip behind a short sentence; three wastes synthesis on cancel.

D-13Tables read in full, rows are skip units

User decision over "header row only". Tables usually carry the result.

D-14Word-level caption highlighting in v1

User decision. The data is already in the Edge stream.

D-15Fallback is not audibly marked

The voice change is obvious. A cue per sentence during an outage would be worse than the outage.

D-1624-hour session expiry; process state shown separately

User decision over 30 minutes. A lunch break must not empty the list. Dead processes mark "ended" rather than removing.

D-17Focus-following deferred

No official API; proxies are unreliable in Orca and Claude Desktop. Revisit after real use.

D-18UserDefaults and Application Support JSON; everything live

Beat flag files under ~/.claude/projects. The prototype's rate flag needed a daemon restart.

D-19Bundled CLI doubles as the hook receiver

The socket is needed for hooks anyway. A shell script would need jq or nc and could not meet 20 ms reliably.

D-20Hooks merged into settings.json, identified by command path

Orca and the user's hooks live in the same file. Back up before every write; refuse malformed input.

D-21Core / Backends / App / CLI targets

The pipeline must be testable without audio hardware; the CLI must not link AVFoundation or AppKit.

D-22Bundle id com.jdforsythe.claudio

Also the UserDefaults suite, Keychain service and logging subsystem.

D-23Documentation as a numbered set, not one file

User decision. Each milestone maps to a small set of documents.

D-24macOS 15 minimum, Swift 6 strict concurrency, swift-format and SwiftLint, GitHub Actions

Keeps modern APIs available while allowing users one release behind. Strict concurrency catches the data races an audio pipeline with actors would otherwise hide.

D-25Final-answer classification: stop_reason, then turn end, then block adjacency

Layered so it is correct whether or not stop_reason is present while a message streams.

D-26claude agents --json is the process-liveness source

Verified locally. Command failure means "unknown", never "ended".

D-27Verified: records are written per message with stop_reason always populated

Measured on 2.1.290 by tailing a live session. The primary classifier is the production path; the transcript's text latency is bounded by message completion.

13Risks a reviewer should weigh

The transcript format is explicitly unstable. Anthropic says it can change in any release. Mitigation: a tolerant parser, layered classification, probe fixtures that fail loudly, the Stop hook as the authority when hooks are on, and a doctor warning when the unknown-record ratio climbs.

edge-tts is unofficial. Microsoft broke the handshake in December 2025 and the Python maintainer patched it. Mitigation: per-sentence fallback to Apple, constants in one file, a mock-server test that pins the protocol, and a live smoke test that detects drift.

Hooks share a file with Orca. Orca rewrites its managed entries in the same settings.json. Mitigation: merge never clobber, backups, verify after write, and a test that asserts byte-identity outside our entries.

Text arrives at message granularity. Measured, not assumed. Narration before a long tool call is spoken only when that call finishes generating. Accepted for v1; MessageDisplay is the documented path to earlier text.

Unverified and flagged in the spec. Whether Apple's synthesizer reports word ranges while writing to buffers rather than speaking live; whether Orca's structured chat mode writes transcripts to the same path. Both have fallbacks and named tests.
